# 海外广告代理业务系统

二级广告代理的内部业务系统 + 客户自助门户。一句话：**客户把钱给我们，我们把钱加到他名下的广告账户里，媒体消耗掉，月底大家能对上账。**

两端的边界很硬：

| 端 | 谁用 | 地址 | 能干什么 |
|---|---|---|---|
| 内部后台 | 员工（销售/风控/财务/运营/管理员） | `/` | 管客户、审批、加款、看全量账 |
| 客户门户 | 客户自己 | `/portal` | 只看自己的数据，发起申请，不能动钱 |

两端 URL 不通、登录页不互通，交叉登录后端直接 403。客户侧永远看不到返点、成本系数、渠道。

---

## 一、业务全景：钱和量是怎么走的

```
① 获客          ② 入驻              ③ 开户              ④ 充值              ⑤ 加款            ⑥ 消耗          ⑦ 对账
portal 登录页 → 客户申请 → 客户管理 → 开户管理 → 广告账户 → 充值管理 → 客户钱包 → 账户管理 → 广告账户 → 消耗报表 → 资金流水
   提交申请       (线索)     三级审核    审批/下户    (主表)     审核入账     (余额+)    冻结→执行    (余额+)    CSV导入    (台账)
                                                客户门户「开户申请」↗        客户门户「我的钱包」↗             客户门户「广告账户」↗
```

四层资金，各记各的账，**永远不重复扣**：

| 层 | 谁的钱 | 加款时 | 消耗时 |
|---|---|---|---|
| 客户子钱包 | 我方欠客户（负债） | **+** 加款金额 | 不动 |
| 一代钱包 | 我方在一代处的余额 | **−** 加款金额 | 不动 |
| 广告账户 | 媒体侧可用预算 | **+** 加款金额 | **−** 消耗金额 |
| 平台钱包 | 我方实持资金 | 打给一代时已出 | 不动 |

> 铁律：**消耗只扣广告账户，不重复扣客户钱包**。客户钱包只在「充值时加、给账户加款时减」两个动作里变。

## 二、内部后台（10 个模块）

菜单按权限动态渲染，没有权限的模块根本不会出现。下表是**模块在链路里的位置**，后面逐个讲怎么用。

| 顺序 | 模块 | 权限码 | 在链路里的角色 | 上下游 |
|---|---|---|---|---|
| 1 | 客户申请 | `client.lead.view` | 获客入口：接门户来的线索 | 上游：门户登录页 → 下游：客户管理建档 |
| 2 | 客户管理 | `client.list` | 客户主档 + 三级审核 + 商务条款 | 上游：客户申请 → 下游：开户、充值、门户登录 |
| 3 | 开户管理 | `open_request.view` | 开户审批，产出广告账户 | 上游：客户已开通 → 下游：账户管理 |
| 4 | 账户管理 | `ad_account.view` | 按广告账户干活（加款操作台） | 上游：开户 → 下游：消耗、交易记录 |
| 5 | 充值管理 | `topup.view` | 客户打款进来，审核入账 | 上游：客户汇款/门户充值 → 下游：客户钱包余额 |
| 6 | 消耗报表 | `spend.import` | 媒体消耗入库 + 经营分析 | 上游：媒体后台导出 → 下游：资金流水、账户余额 |
| 7 | 资金流水 | `ledger.view` | 钱的台账，能核销能冲正 | 上游：钱包流水 + 消耗 → 下游：对账依据 |
| 8 | 资金总览 | `wallet.view` | 一眼看四层资金（只读） | 读全部钱包，不动账 |
| 9 | 问题工单 | `ticket.view` | 客户问题受理 | 上游：门户提交 |
| 10 | 我的档案 | — | 当前登录人与权限码 | — |

### 1. 客户申请（线索）

**解决什么**：门户登录页有「开户申请」，陌生人填公司名+联系方式就能提交。这些**不是客户**，是线索，落在 `client_lead`，不会污染客户列表、也不会产生没人管的门户账号。

**怎么用**：销售认领 → 打电话/加微信 → 标记「已联系」→ 谈成了标「已转客户」→ 黄了标「已关闭」（要填原因）。

**关联**：
- 上游：`POST /api/public/client-applications`（匿名，同一手机/邮箱 7 天内重复提交只留一条，且不回传线索 ID 防探测号码）
- 下游：**转客户不会自动建号**。`client_lead` 表里没有 `client_id` 字段，「已转客户」只是一个状态标记。真正的建档要销售去「客户管理 → 添加客户」手工做。
- 销售只能看到自己认领的 + 未认领的；运营/管理员看全量。

### 2. 客户管理（系统的心脏）

**解决什么**：客户档案 + 入驻审核 + 商务条款，一件事都不能少——没通过审核的客户不能开户、不能充值、登不进门户。

**怎么用**：
- **建档**：填公司名、登录邮箱（必填，这就是门户账号）、初始密码（留空用默认 `123456`）、负责销售/AE、CRM 编号。勾「立即启用」直接 ACTIVE，不勾就进审核流。
- **三级审核**（状态由当前状态推导，前端指定 step 无效）：

  | 步骤 | 状态 | 谁能做 | 做什么 |
  |---|---|---|---|
  | 初审 | `PENDING_REVIEW` | 销售 / 管理员 | 核主体资质 |
  | 风控 | `PENDING_RISK` | 风控 / 管理员 | 合规与风险 |
  | 定额 | `PENDING_LIMIT` | 财务 / 管理员 | 授信额度、成本系数、返点率、账期 |
  | 完成 | `ACTIVE` | — | 可以开户、充值、登录门户 |

  驳回必须填原因，客户在门户能看到并改完重提（版本号 +1，历史不覆盖）。
- **商务条款**：`cost_ratio`（成本系数）、`rebate_rate`（返点率）、`credit_limit`（授信额度）、`payment_terms`（账期天数）。**这三个数字对客户完全不可见**。
- **调账**：直接改客户钱包余额，必须双签 + 幂等单号，走 `post()` 不绕过账本。
- **停用**：`ACTIVE → DISABLED`，停用后不能开新户、不能充值，但历史流水照常参与报表。

**关联**：
- 上游：客户申请（线索）→ 手工建档；或运营直接建档
- 下游：只有 `ACTIVE` 才能 → 开户管理提交申请、充值管理给他加款、客户登录门户
- 侧写：`last_active_at` 记录最近门户登录时间（列表的「活跃」列 = 30 天内登录过）
- 邮箱唯一且不区分大小写；密码 bcrypt 落库，明文只在创建/重置时回显一次

### 3. 开户管理

**解决什么**：向一代/媒体申请开广告账户。当前**只做 TikTok**，FB/Google 存量账户只读保留（不删、不冲正、照常进报表），但不再新建。

**怎么用**：
- 两个来源：门户「开户申请」客户自己提，或后台「代客户提交」。
- **审批要勾 5 项核对清单**（主体/行业/BM/重复开户/渠道），少一项不让过。
- 审批有两条路：
  - **通过并开户**（`auto_complete=true`）→ 直接生成广告账户，单号 `AUTO-<申请单号>-<序号>`，状态 `OPENED`
  - **仅审批** → `PENDING_SUBMIT` → 点「提交到一代」→ `AGENT_REVIEWING` → 收回执 → `OPENED`
- 状态机：`PENDING_APPROVAL → PENDING_SUBMIT → AGENT_REVIEWING → OPENED`，另有 `AGENT_REJECTED` / `REJECTED`。

**关联**：
- 上游：客户必须 `ACTIVE`
- 下游：审批通过产出 `ad_account`，账户管理才有数据；门户「广告账户」也能看到
- 开户单上的 `timezone` 会带进广告账户，账户列表按该时区看余额和消耗日切
- `bm_id` / `bc_ids` 会被「BC 管理」归纳成客户的历史绑定
- **同一客户 + 同媒体 + 同主体**有在办申请时，不允许重复提交

### 4. 账户管理（最常用的页面）

**解决什么**：业务方日常是**按广告账户**干活，不是按加款单干活。所以这个页面以广告账户为主表，加款单退到 Tab 里。

**怎么用**：
- **主表 Tab**：所有广告账户（ID/时区/客户/代理商/平台/开户主体/BC ID/余额/状态/开户时间）。行内「充值」直接对该账户发起加款。
- **充值记录 Tab**（内部就是 `DeskRecharge`）：加款单列表，在这里做**执行、核查、重试、撤销**。

**加款是两步，钱只能由人点出去**：

```
发起（任何有 topup 权限的人）
   └→ 冻结客户钱包的可用额（balance 不减，frozen 加）→ 单据 PENDING_EXEC
         └→ 运营点「执行」→ 解冻 → 客户钱包 −金额 → 广告账户 +金额 → SUCCESS
```

| 状态 | 含义 | 出口 |
|---|---|---|
| `PENDING_EXEC` | 待执行（钱已冻结） | 执行 / 撤销（撤销必须解冻） |
| `SUCCESS` | 已到账 | 终态 |
| `REJECTED` | 一代拒绝 | 重试 或 撤销 |
| `TO_VERIFY` | 结果未知（网络超时） | **冻结不动**，人工核实后 resolve |
| `CANCELLED` | 已撤销 | 终态，冻结已释放 |

**关联**：
- 上游：客户钱包必须有余额（来自充值管理）；开户管理必须先产出账户
- 下游：广告账户余额被消耗报表扣减；交易记录（`ADTR` 流水号）来自这里的加款单
- 唯一键 `request_no`（前端每次开弹层生成 UUID），连点不会重复冻结
- 平台熔断开关在「充值记录」Tab 里（按媒体维度），熔断后拒绝发起

### 5. 充值管理（线下汇款申请单）

**解决什么**：客户打钱进来，钱到账了才能给他加款。这张单是**唯一的人工风控点**——没凭证就入账，等于留下一笔永远无法自证的流水（而流水按铁律不可删改）。

**怎么用**：
- 发起申请：选客户、资金账户类型（**现金账户** / **授信账户**）、操作类型（加款 / 减款）、金额、银行流水号、凭证。
- 审核通过才动账，且只动一次：

| 账户 | 操作 | 审核通过后 |
|---|---|---|
| 现金账户 | 加款 | 客户钱包 **+** 金额（幂等键 `topup:<id>`） |
| 现金账户 | 减款 | 客户钱包 **−** 金额（余额不足直接 400） |
| 授信账户 | 加款 | **是还款**：`credit_used` 减少（客户把欠款还进来） |
| 授信账户 | 减款 | 占用授信：`credit_used` 增加（超额度拒绝） |

- **凭证闸口**：无凭证要填不少于 5 字的「无凭证原因」，写进流水备注 + 审计日志；凭证是 `/api/files/` 地址时校验磁盘真的存在，文件丢了直接拒绝入账。
- 大额二次确认：折合超过 5000 USD 要二次确认（阈值可在 `system_setting` 改）。

**关联**：
- 上游：客户线下汇款 / 门户充值（门户走央行中间价折人民币应付，服务端下单重新取价，漂移超 0.2% 报 `RATE_CHANGED` 让客户重确认）
- 下游：**客户钱包余额增加 → 账户管理才能给广告账户加款**。这是"充值 → 加款"之间唯一的口子。
- 授信账户不动现金，因此不写钱包流水，只写审计日志
- 旧接口 `/api/desk/topups`（代录/确认到账/退回/冲正）保留给门户与回归测试，页面只走新流程

### 6. 消耗报表

**解决什么**：媒体花了多少钱，必须进系统，否则报表、对账、月结全是空的。

**怎么用**：
- **导入**：支持媒体后台导出的中文表头 CSV（账户ID/日期/GMV Max总消耗/…/转化数），也兼容老格式。导入**先 dry_run 预校验**，不落库；确认后再导。`account_id + date` 是唯一键。
- **看数**：数据概览 KPI（总消耗 / GMV Max 总消耗 / BC 总消耗）+ TOP10 客户 + 按天折线（纯 SVG，悬停 tooltip）+ 四个报表 Tab（客户 / 账户 / 销售 / 代理商），`mode=summary` 看汇总（带环比），`mode=daily` 拆到天；另有一个「消耗明细」视图。
- **口径**：总消耗 = GMV Max + BC；净消耗 = GMV Max 净 + BC 净；曝光/点击/转化只挂 BC 侧；**一次只算一个币种**（跨币种求和无业务意义）。

**关联**：
- 上游：媒体后台导出文件；广告账户必须先存在
- 下游：写 `spend_daily` 并**扣减广告账户余额**（可扣成负数，不拦截——那是媒体侧真实花费）；数据同时喂给「资金流水 → 账户消耗 Tab」
- 异常标记（`SPIKE` 单日超 7 日均值 3 倍 / `ZERO_SPEND` 有余额但零消耗）是**展示期实时算**，不落库——异常是"看的时候的现象"，不是事实

### 7. 资金流水（台账）

**解决什么**：一行一笔钱，能回答"这笔钱谁动的、动之前多少、动之后多少"。

**怎么用**：
- **流水 Tab**：列按运营台账口径（ID / 账单ID / 客户 / 代理商 / 广告账户 / 交易类型 / 交易金额 / 交易前余额 / 交易后余额 / 备注 / 创建时间）。筛单一客户时，表格上方多一条「期初 → 期末 / 进 / 出 / 未核销」对账条。
- **账户消耗 Tab**：另一张表（`spend_daily`），口径不变。
- **核销**：勾选流水标记「已核销」。核销是独立事实，**不给流水加字段、不改流水**。
- **冲正**：双签，只**新增一条反向红字**，原流水一个字不改。
- 导出 xlsx / csv，列与页面一致。

**关联**：
- 上游：数据源是 `wallet_transaction`（客户钱包流水），加款类流水还能反查 `recharge_order → ad_account` 带出代理商和账户
- 下游：对账依据。期初 = 筛选起始时间之前该钱包 seq 最大的 `balance_after`
- **交易类型不是 biz_type**：同一个 biz_type 的进出是两种动作（充值 vs 减款），映射表在 `services/ledger_flow.py`；冲正流水的类型要递归追到根流水，否则第二层冲正会被归成"充值"这种不存在的动作
- 流水不可改：ORM 事件 + SQLite 触发器双保险，连裸 SQL `UPDATE` 都被 abort

### 8. 资金总览

按币种分列展示四层资金（客户子钱包 / 一代钱包 / 平台钱包 / 各广告账户合计），只读页面，不动账。

> 「账本自检」面板目前**已从页面下线**（`DeskOverview.tsx` 里整块注释保留）。校验能力还在接口上，
> 需要时手工调 `POST /api/desk/wallets/verify-all`：逐钱包校验 `seq` 连续性与 `balance_after` 首尾相接，任何断号都会报出来。

### 9. 问题工单

**怎么用**：门户提交 → 后台受理 → `PENDING → PROCESSING → RESOLVED / CLOSED`，结单可重开。**结单必须有回复**，否则客户问题会被静默关掉。多次回复按时间追加在同一字段，不覆盖历史。

**关联**：销售只能碰自己名下客户的工单（`scope_sales_owner`）。

### 10. 我的档案

当前登录人的角色和 40 个权限码，前端菜单就是按这个列表过滤的。**改权限去 `rbac.MATRIX`，不要在前端硬编码角色判断。**

## 三、客户门户（6 个模块）

客户侧所有接口的 `client_id` **只从登录态取**，URL 或 body 里塞 `client_id` 完全无效；操作别人的单据按 404 处理，不暴露存在性。

| 模块 | 客户能做什么 | 数据来源 | 和后台的关联 |
|---|---|---|---|
| 我的钱包 | 看可用/冻结、看流水、发起充值、授信还款 | 客户子钱包 | 充值要等后台「充值管理」审核到账 |
| 广告账户 | 看账户、看明细、发起充值、导出 | `ad_account` | 账户来自后台开户；充值由后台执行 |
| BC 管理 | 维护 BCID 绑定、设默认、删除 | `client_bcid` | 默认项决定开户申请预选；历史绑定从开户单归纳 |
| 开户申请 | 提交开户、上传执照 OCR 带出企业信息、看进度 | `open_request` | 后台「开户管理」审批 |
| 交易记录 | 看广告账户充值单的执行结果 | `recharge_order` | 只读投影，没有动账按钮 |
| 问题工单 | 提交问题、看处理说明 | `portal_ticket` | 后台「问题工单」受理 |

### 1. 我的钱包

- 可用 / 冻结**分列**（冻结 = 已发起加款但还没执行的钱）
- 资金账户流水：只有自己的，返点类流水已被过滤
- **充值**：填到账美金 → 实时拉汇率报价 → 显示应付人民币（向上取整到分）→ 提交后是 `PENDING_PAY`，财务确认才入账
- **授信还款**：提交申请，财务审核后恢复额度
- 汇率失效（供应商全挂超过 24h）返回 503 拒绝报价，**不拿旧汇率收钱**

### 2. 广告账户

- 主表：媒体 / 账户 ID / 余额 / 状态 / 开户审核 / 时区 / 开户主体 / 最近充值，可筛选可导出
- 明细抽屉：账户信息、现金可用/冻结、近 30 天消耗、最近充值
- **发起充值**：从自己的现金钱包扣（冻结），落 `PENDING_EXEC` 加款单，等运营在后台执行。**客户没有任何直接出账入口。**
- 白名单返回：渠道、成本系数、返点率、代理商一律不下发，CSV 同样过滤

### 3. BC 管理

- 两种来源：`HISTORY`（从广告账户 `bm_id`、开户单自动归纳）、`MANUAL`（客户手填）
- 同一客户最多一个默认项，开户申请页把它放第一位并预选
- **删除留墓碑**（软删）：只删绑定关系，不动广告账户和历史开户单；但删完刷新不会回来——历史归纳会跳过墓碑。重新添加同一个号会复活原行，不产生重复。

### 4. 开户申请

- 上传营业执照/BR → 本地 OCR（离线 onnx 模型，不上传第三方）自动带出名称、信用代码、注册地
- 识别结果**只填空白字段**，用户手改过的值不会被换图冲掉
- 识别不出就走降级链：OCR → 客户档案 → 文件名 → 手工填，全程 `parsed=false` 但绝不伪造
- 进度按状态显示：待审批 → 一代审核中 → 已下户 / 已驳回（可重提）
- **入驻未完成时，这个页面顶部先显示入驻进度**（`PortalProfile` 内嵌，不是独立菜单）：还没提交就引导填入驻资料，被驳回就改完重提（版本 +1，历史不覆盖）。入驻通过后才出现「提交开户申请」

### 5. 交易记录

看的是**广告账户充值单的执行结果**，不是资金账户流水：

| 页面 | 看什么 | 有余额变化吗 |
|---|---|---|
| 我的钱包 → 资金流水 | 资金账户收支台账（充值/加款/冲正/前后余额） | 有 |
| 交易记录 | 广告账户充值单（ADTR 流水号、媒体侧到账状态、失败原因） | 没有余额列 |

只下发 12 个字段，业务单号（RC…）、客户名、代理商、渠道、重试次数一律不返回；反馈只给结论（已到账/失败已退回/确认中/已撤销已退回），不透传内部回执原文。

### 6. 问题工单

客户在门户提交问题，能看到内部的处理说明。状态：`PENDING → PROCESSING → RESOLVED / CLOSED`，已结单可以追加重开。

**关联**：落到 `portal_ticket`，后台「问题工单」受理。结单必须有回复，否则客户问题会被静默关掉。

## 四、五条关键链路（跨模块串讲）

### 链路 A：陌生访客 → 付费客户

```
门户登录页「开户申请」（匿名，不用登录）
   → 后台「客户申请」出现线索 NEW
   → 销售认领 → CONTACTED → 电话/微信谈
   → 谈成：去「客户管理 → 添加客户」建档（填登录邮箱=门户账号）
   → 三级审核：销售初审 → 风控 → 财务定额
   → ACTIVE：客户可以用邮箱+密码登录门户，可以开户、可以充值
```

⚠️ 线索表**没有** `client_id`，「已转客户」只是状态标记，不会自动建档。

### 链路 B：开户

```
客户门户「开户申请」（上传执照，OCR 带出企业信息，选 BC）
   → 后台「开户管理」待处理
   → 审批勾 5 项清单
   → 通过并开户：直接生成 ad_account（AUTO-xxx），OPENED
     或 仅审批 → 提交到一代 → 一代审核中 → 收回执 → OPENED
   → 客户门户「广告账户」看得到，后台「账户管理」也有了
```

### 链路 C：钱从客户到广告账户（最核心的一条）

```
① 客户打款
   客户门户「我的钱包 → 充值」或线下汇款
       → 后台「充值管理」待审核
       → 财务审核通过
       → 【客户钱包 +金额】，写一条 TOPUP 流水
② 给广告账户加款
   后台「账户管理」行内「充值」或客户门户「广告账户 → 充值」
       → 冻结客户钱包可用额（balance 不变，frozen +）→ PENDING_EXEC
       → 运营点「执行」
       → 解冻 → 【客户钱包 −金额】→【广告账户 +金额】→ SUCCESS
       → 一代钱包 −金额（渠道有钱包时）
```

**两个"必须"**：必须人点执行（铁律 4，没有任何自动加款），未知结果必须人工核查（铁律 6，`TO_VERIFY` 不解冻）。

### 链路 D：消耗

```
媒体后台导出 CSV
   → 后台「消耗报表 → 导入消耗」先 dry_run 预校验（行号级报错）
   → 确认导入 → spend_daily 落库 + 【广告账户余额 −消耗】
   → 「消耗报表」四维分析 ／ 「资金流水 → 账户消耗」看明细
```

### 链路 E：月底对账

| 你想知道 | 去哪看 |
|---|---|
| 这个客户这个月进出多少、还剩多少 | 资金流水 → 筛该客户 → 顶部「期初→期末」对账条 |
| 这个账户的钱花哪了 | 资金流水 → 账户消耗 Tab；或 消耗报表 → 账户 Tab |
| 这笔钱谁动的、动错了吗 | 资金流水 → 找流水 → 核销 或 冲正（双签） |
| 账本有没有算错 | 调 `POST /api/desk/wallets/verify-all`（页面自检面板已下线） |
| 客户看到的和内部一致吗 | 门户「我的钱包」vs 后台「客户管理」该客户 |

## 七、数据库

本地 SQLite 单文件 `data/app.db`，零安装。

- 首次启动自动建表 + 灌种子数据
- 表结构升级走 `migrate.py` 增量 ALTER，**不删库、不丢数据**
- 换 Postgres：改 `.env` 的 `DATABASE_URL` 一行，代码不动
- 重置演示客户审核状态：`POST /api/dev/reset-demo`（只清审核记录，不动流水）
- 金额一律自定义 `Money` 类型：SQLite 存 BIGINT（金额 ×10000），Postgres 存 `NUMERIC(20,4)`，**永远不出现 float**

> **部署提示**：前端是单页应用，`/portal` 不是真实目录。exe 版已内置 SPA fallback；用 Nginx 自己部署时要配
> `try_files $uri $uri/ /index.html;`，否则刷新 `/portal` 会 404。

## 九、改代码前的三条铁律

1. **余额只能由 `ledger.post()` / `freeze()` 改**，直改会被 `guards.py` 抛 `ImmutableViolation`；`session.flush()` 必须在 `allow_balance_mutation()` 内部。
2. **流水只追加**，纠错只能 `reverse()` 新增红字；连裸 SQL `UPDATE wallet_transaction` 都会被触发器 abort。
3. **钱只能由人点出去**，不允许任何自动生成加款单的逻辑；`unknown`/`TO_VERIFY` 在人工核查前不动账。

完整约定见 `AGENTS.md`，设计取舍见 `DESIGN.md`。
